# Редактор: доработки после ревью — план

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** закрыть известные недоработки редактора, не зависящие от реального GitLab: комментарии и форматирование при правке YAML, структура `main.ts`, мелкие замечания ревью.

**Spec:** `_docs/specs/2026-11-18-arch-editor-design.md` (§6 — минимальный diff, анти-цель «потеря ручного форматирования и комментариев»).

**Git:** ветка `feature/editor`, коммиты `feat|fix|refactor(arch-editor): Follow-up N — <название>` с трейлером `Co-Authored-By`. Push — только по команде пользователя.

## Global Constraints

- Все существующие тесты (`npx vitest run`, `npm run test:e2e`, `npx tsc --noEmit`) остаются зелёными; поведение CLI не меняется.
- Браузерный код (`editor/**`, `viewer/**`, `src/model/{types,names,schemas,resolve,loadFiles}.ts`) не импортирует модули Node.
- `patchYaml` сохраняет проверку результата: перечитанный текст обязан совпадать с целевыми данными, иначе — ошибка, файл не меняется.
- Тексты UI — на русском; DOM — через `h()`/`textContent`, без `innerHTML` с данными.

### Task 1: правка YAML без потери комментариев внутри блоков

**Files:** Modify `_tool/editor/yamlEdit.ts`; Test `_tool/test/editor-yaml.test.ts`.

Сейчас изменённый список или map верхнего уровня переписывается целиком: теряются комментарии внутри него и в строке ключа, вложенный блочный map сворачивается во flow, последовательность с отступом 4 переиндентируется, блочные скаляры `|`/`>` становятся строкой в кавычках, у файлов с CRLF вставки получают `\n`.

- [ ] **Step 1: failing tests** (каждый — построчный diff на реальном тексте):
  - изменён один скаляр внутри блочного map второго уровня (`nfr:` → `slo`), внутри есть комментарии `# …` на других строках и в строке ключа `nfr: # почему` → diff ровно 1 строка, все комментарии на месте;
  - вложенный блочный map внутри блочного map (`overrides:` → `tls:` → `p`) — изменение одного значения → 1 строка, блочный стиль сохранён;
  - элемент списка изменён точечно (`uses[1].access: rw → ro`, элементы — flow `{ … }`, между элементами комментарий) → 1 строка, комментарий на месте;
  - в список добавлен элемент в конец → только добавленные строки; удалён элемент из середины → только его строки (и его собственный комментарий-строка над ним);
  - последовательность с отступом 4 (`uses:\n    - {…}`) — изменение одного элемента → 1 строка, отступ 4 у новых/изменённых строк;
  - блочный скаляр `description: |` — изменение текста → стиль `|` сохранён, меняются только строки текста;
  - файл с CRLF — любая правка (замена, вставка ключа, удаление) → во всём результате только `\r\n`;
  - удаление ключа с комментарием-строкой непосредственно над ним → комментарий удаляется вместе с ключом;
  - идемпотентность `patchYaml(x, parse(x)) === x` для всех YAML демо и фикстур остаётся;
  - защита: подстроенный случай, где точечная правка невозможна (якоря/алиасы), по-прежнему бросает ошибку или откатывается на замену всего значения с успешной проверкой.
- [ ] **Step 2: implement.** Рекурсивная точечная правка по диапазонам узлов: map — по ключам (рекурсия); список — сопоставление элементов (одинаковые остаются нетронутыми, изменённые правятся рекурсивно или заменяются по одному, добавленные вставляются в стиле соседей, удалённые вырезаются со своими строками); при невозможности — замена значения целиком в стиле оригинала (как сейчас). Стиль и отступ новых строк — по соседним элементам; EOL — по файлу. Проверка результата сохраняется.
- [ ] **Step 3:** `npx vitest run`, `npx tsc --noEmit`, `npm run test:e2e` — PASS.

**Files:** по пунктам; Test — соответствующие `test/*.test.ts`.
